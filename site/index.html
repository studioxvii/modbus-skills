Modbus Skills

Tested, read-only workflows for Modbus engineering.

Chained workflows

  • Review a register map
  • Determine byte order from supplied raw words
  • Probe, resolve byte order, and finalize a tool pack
  • Build a multi-target tool pack
  • Analyze bounded read data
  • Compare map revisions

Researched problems

  • Users and tools can mix zero-based protocol offsets with one-based or 3xxxx/4xxxx reference notation.
  • The same numeric offset can exist in coils, discrete inputs, input registers, and holding registers.
  • Values wider than 16 bits can require different word and byte layouts.
  • Coil and packed-bit order can be confused with multi-register byte order.
  • Several independent polls on one serial route can contend and fail when requests are not queued.
  • A configured polling interval can differ from observed request frequency.
  • Unit identifier zero has transport and tool-specific behavior and can represent broadcast behavior in serial contexts.
  • A read block can become invalid when its start and quantity cross the server's defined data range.
  • A device can return a byte count or frame length that does not match the received payload.
  • Site work benefits from a reusable configuration that defines poll blocks and named references.
  • Production and commissioning tests need repeatable request and expected-response sequences.
  • A reusable Modbus Poll setup needs a documented and versioned file contract.

Apply Modbus Review Decisions

Apply explicit human review decisions to a normalized Modbus map, preserve the decision evidence, exclude out-of-scope points, and approve the map only when no blocking hold remains. Use after evidence review or byte-order evaluation when a user confirms values or dispositions.

Ask Modbus

Also use as the safety stop for requests that ask for Modbus writes, broadcasts, network discovery, or unbounded polling. Do not use as the primary skill when a safe request names a concrete input, conversion, check, analysis, or target output that matches another skill.

Compare Modbus Maps

Use $compare-modbus-maps to find added, removed, and changed register points.

Lint Modbus Map

Validate a normalized Modbus map for duplicate identities, overlaps, invalid ranges, datatype-width conflicts, area and function-code conflicts, unresolved fields, unsafe writes, and scoped byte-order inconsistencies. Use when explicit map fields exist and the goal is deterministic validation only. Use diagnose-modbus-map for end-to-end cleanup of a raw or messy map.

Use $lint-modbus-map to check this register map for conflicts and unsafe assumptions.

Normalize Modbus Map

Normalize a candidate Modbus map into explicit protocol offsets, register areas, unit identifiers, datatypes, word counts, access values, and byte-order states. Use after parsing or to represent mixed or unresolved source conventions without a requested map-wide conversion. Use remap-modbus-addresses when the user asks to convert a map between known conventions.

Use $normalize-modbus-map to normalize this map without guessing unresolved fields.

Parse Modbus Map

Parse Modbus register maps from CSV, JSON, XML, XLSX, or structured text into candidate-map artifacts with source values, rejected rows, warnings, assumptions, and holds. Use when a user supplies a register list or wants a machine-readable map without silent engineering guesses.

Use $parse-modbus-map to parse this register map into a reviewed artifact.

Remap Modbus Addresses

Preview and apply a requested map-wide conversion between protocol offsets, one-based offsets, and Modicon reference notation, with explicit areas and collision checks. Use when the source and target conventions are known. Use normalize-modbus-map first when source conventions or engineering fields remain mixed or unresolved.

Use $remap-modbus-addresses to preview a safe address-convention conversion.

Review Modbus Evidence

Review Modbus parsing evidence, rejected rows, inferred values, assumptions, warnings, and blocking holds. Use before promoting a candidate map, after PDF extraction, or when a user needs to know which register-map fields are confirmed versus inferred.

Use $review-modbus-evidence to show what is confirmed and what still needs review.
