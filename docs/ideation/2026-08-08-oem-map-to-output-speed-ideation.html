OEM map to output in minutes

The central change is not “fewer approvals.” It is changing the product from a shelf of stage-oriented skills into an outcome compiler: the user states what they need, the system completes every safe local step, and humans see only material exceptions.

Grounding Context

The reference task showed the same design defect repeatedly. A PDF extractor asked for pages it could discover, installed Poppler in the critical path, failed on merged table cells, and recovered through bespoke code. The next stages required adapters because the candidate schema did not compose with the evidence reviewer. Review began page by page. Normalization mixed OEM facts with site binding and repeated map-wide uncertainty per point. “Plan reads” did not select measurements. Finally, the zero-gap planner generated six Node-RED getters for a legal bounded range that an experienced user immediately recognized as one FC03 read.

The repository’s stated policy is already correct: optimize for minutes of human attention, automate deterministic work, group exceptions by root cause, and preserve canonical contracts. The runtime and public workflow have not yet caught up with that policy.

Decisive point of view

Skills should remain internal compiler passes. The primary user surface should be one offline-first outcome workflow. Granular skills stay available for inspection and expert use, but ordinary users should never have to operate the artifact graph.

External prior art reinforces this direction: document systems use field confidence and source anchors; table tools support multiple extraction strategies and quality metrics; compiler pipelines separate source evidence from typed semantic representations; lineage systems preserve source-to-output traceability; and Modbus FC03/04 reads are bounded contiguous ranges that can be packed deterministically.

I1. Offline-first outcome compiler

Axis 5 · OrchestrationConfidence 96%Complexity High

Description: Add one primary workflow—working name build-device-project—that accepts an OEM manual, plain-language measurement intent, optional connection settings, and requested output targets. It owns page discovery, extraction, review, semantic compilation, selection, map rendering, read packing, output generation, and offline verification. Intermediate artifacts remain auditable under a machine subdirectory; the user sees a finished bundle or one phase-scoped exception packet.

Basis
direct: modbus-help recommends and stops, review-map excludes PDF extraction, and the reference user had to invoke and bridge each stage manually.
Rationale
The real unit of work is not “normalize a map”; it is “turn this manual into the map and output I need.” Retaining stage skills internally preserves engineering clarity without charging the user for it.
Downsides
The orchestrator must define hard boundaries: safe offline work continues automatically; live-device access remains explicit and bounded. Error and resume semantics become a first-class architecture concern.

Illustrative direction: the internal passes remain; the user-facing choreography disappears.

2

I2. Quality-gated extraction ladder

Axis 1 · ExtractionConfidence 95%Complexity High

Description: Automatically locate likely Modbus page clusters, then try a deterministic strategy ladder: native structured text, layout-preserving text, coordinate reconstruction, and local OCR/layout extraction. Every strategy emits the same evidence contract. Coverage, address continuity, width/type consistency, duplicate detection, cross-page headers, and parser disagreement determine whether the result advances; only anomalous cells or regions enter review.

Basis
direct: The strict parser returned zero rows on merged cells while an ad hoc coordinate method recovered 149 candidates. Page discovery, OCR preparation, and dependency installation occurred outside the executable workflow. external: Camelot, AWS Textract, and Google Document AI support strategy selection, source geometry, confidence, and quality-based review routing.
Rationale
OEM manuals are layout documents, not reliably delimited text files. Parser failure should be an expected branch with comparable evidence—not a reason to invent one-off scripts.
Downsides
Multiple strategies increase runtime and test surface. Confidence must be calibrated on representative fixtures; agreement between two weak strategies is not proof.
3

I3. Three-layer map model

Axis 2 · ContractsConfidence 95%Complexity High

Description: Separate three concerns that are currently fused. The OEM semantic map stores reusable source-backed vendor facts. The user map selection stores the measurements, names, groups, priorities, and display choices a person wants. The device binding stores TCP/RTU route, endpoint, unit ID, area overrides, target constraints, and live evidence. A bound operational projection joins them only when an output needs it.

Basis
direct: Current canonical identities include route and unit, making site facts into per-point normalization holds and preventing an otherwise useful OEM catalog. external: Compiler intermediate representations and OpenLineage separate source truth, semantic transformation, and consumer-specific projection.
Rationale
One reviewed OEM map should serve many devices and many user selections. Changing an IP or unit must not invalidate source review or point identity.
Downsides
Requires a schema migration and explicit join/provenance rules. Too many user-visible files would recreate the original UX defect, so the layers must remain internal by default.

Illustrative direction: reusable facts, human intent, and site binding have independent lifecycles.

4

I4. Phase-scoped decision transaction

Axis 3 · InteractionConfidence 93%Complexity Medium

Description: Render every currently answerable independent exception in one plain-language packet with scope, consequence, recommended disposition, and affected count. Compile a reply such as “all pages are correct; retain 339/340 as unlabeled” into exact hash-bound records and resume automatically. If a later physical sample creates genuinely new byte-order evidence, that is a new phase and may produce one later packet—it does not justify serial questions now.

Basis
direct: Grouped decision artifacts now exist, but the runtime is stateless, receipts omit actionable context, and users or agents must author decision JSON and restart stages manually.
Rationale
The unit of human review should be an independent engineering judgment, never a page, row, point, file, or internal stage. Scope widening must be automatic when a user says “every page.”
Downsides
Natural-language compilation must be conservative and echo the exact typed interpretation before applying it. A universal “one question ever” promise would be unsafe and is explicitly rejected.
5

I5. Intent-first user map with slice readiness

Axis 4 · Intent and outputsConfidence 94%Complexity Medium

Description: Make “what do you want from this device?” part of planning. Translate goals like power, phase voltage/current, frequency, energy, alarms, and status into an editable included / maybe / excluded selection with categories, aliases, descriptions, units, and source links. Produce a concise CSV plus a readable HTML view by default. Compile selected eligible points while preserving unresolved or irrelevant rows in an exception annex.

Basis
direct: The user correctly challenged “isn’t that what plan reads is for?” Current planning consumes every active point; there is no selection schema, no category vocabulary, and no standard organized human map output.
Rationale
The product is not a 1.2 MB normalized vendor dump. It is a traceable, purpose-specific map that a human can understand and an output backend can consume.
Downsides
Semantic matching can be wrong; uncertain matches need a “maybe” state and cannot silently enter a live plan. Domain starter sets should remain suggestions, not universal truths.
6

I6. Evidence-aware read optimizer

Axis 5 · PlanningConfidence 96%Complexity Medium

Description: Plan from the selected points and optimize for the fewest legal bounded requests—not for zero unused addresses. Automatically bridge intervening addresses only when the OEM semantic map proves the span is readable and compatible in route, unit, area/function, polling class, device quantity limit, and multiword boundaries. Unknown, reserved, write-only, or explicitly hazardous spans force a split. Each plan explains padded addresses and why every block was formed.

Basis
direct: max-gap 0 produced six requests for selected points spanning 257–308; the user immediately identified a one-request FC03 alternative. external: The Modbus specification defines bounded contiguous FC03/04 register reads, making this a deterministic interval-packing problem once semantics are known.
Rationale
“Unselected” is not the same as “unknown” or “unsafe.” The current planner conflates them and emits visibly inferior target flows.
Downsides
Some devices reject broad legal reads. Device-specific maximum spans and known bad ranges must be binding-level constraints; the planner should preserve a strict dense policy as an explicit fallback.

Illustrative direction using the reference selection; actual merging still depends on documented readable spans and device limits.

7

I7. Transcript speed and fidelity contract

Axis 1 · Quality systemConfidence 91%Complexity Medium

Description: Turn the user goal into release criteria. Replay privacy-safe pathological manuals and workflow transcripts and record time to first organized map, questions per phase, repeated decisions, dependency readiness, ad hoc adapter count, row accounting, exception count, output size, read-block count, deterministic hashes, and unsafe-operation count. Calibrate extraction review thresholds on verified fixtures and track errors captured per minute of human attention.

Basis
direct: Existing tests validate deterministic artifacts but not PDF page discovery, merged-cell extraction, human questions, resume behavior, or read efficiency. external: Google Document AI emphasizes threshold evaluation; confidence research warns that raw model confidence is not sufficient.
Rationale
“Within minutes” and “simple” will drift unless they are measurable. Outcome-level tests catch the exact failure where every isolated command passes but their composition wastes 35 minutes.
Downsides
Wall-clock CI budgets can be noisy. Use stable stage timings and interaction counts as hard gates, with wall time as a trend unless the runtime is controlled. Live byte-order workflows require separate later-phase budgets; they cannot be collapsed into the offline target.

The review issue is a corpus-wide pattern: internal granularity leaks into human work. The same redesign rule applies differently across the skills.
